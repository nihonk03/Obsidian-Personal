## LÓGICA DE NEGOCIO — REGLAS ABSOLUTAS

1. **Fuente de verdad colaborativa**: Las 3 carpetas (`core/`, `docs/`, `.agent/`) pueden recibir cambios desde PitayaCore O desde cualquier subdominio. Quien pushea primero actualiza PitayaCore, y PitayaCore replica a todos los demás.
    
2. **Al HOST solo va `core/`**: `docs/` y `.agent/` NUNCA se suben al servidor Hostinger. Solo se sincronizan entre repositorios de GitHub.
    
3. **Las 3 carpetas se mantienen idénticas** en PitayaCore y en los 3 repos de subdominios.
    
4. **Los deploys existentes NO se interrumpen**: Los `deploy.yml` actuales continúan funcionando exactamente igual para sus carpetas de negocio (modulos/, api/, ajax/, etc.). Solo se les agrega la exclusión de las 3 carpetas si no la tienen ya.
    
5. **Sin intervención manual**: Todo debe ser automático vía GitHub Actions. No hooks locales.
    
6. **Escalable**: Agregar un nuevo subdominio debe requerir solo 2 pasos: a. Agregar el repo al array en `sync-to-subdomains.yml` de PitayaCore b. Copiar los 2 workflows nuevos al nuevo repo

## ARCHIVOS A CREAR

### ARCHIVO 1: `PitayaCore/.github/workflows/sync-to-subdomains.yml`

```yaml
name: 🔄 Sync PitayaCore → All Subdomains

on:
  push:
    branches: [ main ]
    paths:
      - 'core/**'
      - 'docs/**'
      - '.agent/**'

jobs:
  sync:
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        subdomain:
          - repo: "erp.batidospitaya.com"
            path_secret: "HOSTINGER_PATH"
          - repo: "api.batidospitaya.com"
            path_secret: "HOSTINGER_PATH_API"
          - repo: "talento.batidospitaya.com"
            path_secret: "HOSTINGER_PATH_TALENTO"

    steps:
      - name: 🚀 Dispatch a ${{ matrix.subdomain.repo }}
        uses: peter-evans/repository-dispatch@v3
        with:
          token: ${{ secrets.SYNC_TOKEN }}
          repository: MiguelGotea/${{ matrix.subdomain.repo }}
          event-type: pitayacore-sync
          client-payload: |
            {
              "sha": "${{ github.sha }}",
              "path_secret": "${{ matrix.subdomain.path_secret }}",
              "triggered_by": "PitayaCore"
            }
```

### ARCHIVO 2: `[subdominio]/.github/workflows/receive-core-sync.yml`

> Crear este archivo IDÉNTICO en los 3 subdominios. La única diferencia es el path_secret que viene en el payload del dispatch.

```yaml
name: 📦 Receive PitayaCore Sync

on:
  repository_dispatch:
    types: [ pitayacore-sync ]

jobs:
  sync-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - name: 📥 Checkout subdominio
        uses: actions/checkout@v4
        with:
          token: ${{ secrets.SYNC_TOKEN }}
          fetch-depth: 0

      - name: 📥 Checkout PitayaCore en SHA específico
        uses: actions/checkout@v4
        with:
          repository: MiguelGotea/PitayaCore
          token: ${{ secrets.SYNC_TOKEN }}
          ref: ${{ github.event.client_payload.sha }}
          path: _pitayacore

      - name: 🔄 Actualizar las 3 carpetas desde PitayaCore
        run: |
          rsync -av --delete _pitayacore/core/   ./core/
          rsync -av --delete _pitayacore/docs/   ./docs/
          rsync -av --delete _pitayacore/.agent/ ./.agent/
          rm -rf _pitayacore

      - name: 💾 Commit y push si hay cambios reales
        run: |
          git config user.name "PitayaCore Bot"
          git config user.email "bot@batidospitaya.com"
          git add core/ docs/ .agent/

          if git diff --staged --quiet; then
            echo "ℹ️ Sin cambios nuevos que commitear"
          else
            git commit -m "chore(core): sync from PitayaCore@${{ github.event.client_payload.sha }}"
            git push
            echo "✅ 3 carpetas sincronizadas en el repo"
          fi

      - name: 🔑 Configurar SSH para deploy al host
        uses: webfactory/ssh-agent@v0.8.0
        with:
          ssh-private-key: ${{ secrets.HOSTINGER_SSH_KEY }}

      - name: 📤 Deploy core/ → HOST (SOLO core/, nunca docs/ ni .agent/)
        run: |
          DEPLOY_PATH="${{ secrets[github.event.client_payload.path_secret] }}"
          echo "📤 Deploying core/ to $DEPLOY_PATH/core/"

          rsync -avz --delete \
            -e "ssh -o StrictHostKeyChecking=no -p 65002" \
            ./core/ \
            ${{ secrets.HOSTINGER_USER }}@${{ secrets.HOSTINGER_HOST }}:${DEPLOY_PATH}/core/

      - name: ✅ Verificar deploy
        run: |
          echo "✅ core/ deployado exitosamente al host"
```

### ARCHIVO 3: `[subdominio]/.github/workflows/propose-core-update.yml`

> Crear este archivo IDÉNTICO en los 3 subdominios.

```yaml
name: ⬆️ Propose Core Update → PitayaCore

on:
  push:
    branches: [ main ]
    paths:
      - 'core/**'
      - 'docs/**'
      - '.agent/**'

jobs:
  propose:
    runs-on: ubuntu-latest
    steps:
      - name: 📥 Checkout subdominio (con los cambios del push)
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: 📥 Checkout PitayaCore (HEAD actual)
        uses: actions/checkout@v4
        with:
          repository: MiguelGotea/PitayaCore
          token: ${{ secrets.SYNC_TOKEN }}
          path: _pitayacore
          fetch-depth: 0

      - name: 🔍 Comparar las 3 carpetas vs PitayaCore
        id: diff
        run: |
          DIFF_CORE=$(diff -rq --exclude='.gitkeep' ./core/   _pitayacore/core/   2>/dev/null || true)
          DIFF_DOCS=$(diff -rq --exclude='.gitkeep' ./docs/   _pitayacore/docs/   2>/dev/null || true)
          DIFF_AGENT=$(diff -rq --exclude='.gitkeep' ./.agent/ _pitayacore/.agent/ 2>/dev/null || true)

          if [ -n "$DIFF_CORE" ] || [ -n "$DIFF_DOCS" ] || [ -n "$DIFF_AGENT" ]; then
            echo "has_diff=true" >> $GITHUB_OUTPUT
            echo "⚡ Diferencias detectadas vs PitayaCore HEAD"
            echo "--- core diff ---"
            echo "$DIFF_CORE"
            echo "--- docs diff ---"
            echo "$DIFF_DOCS"
            echo "--- .agent diff ---"
            echo "$DIFF_AGENT"
          else
            echo "has_diff=false" >> $GITHUB_OUTPUT
            echo "ℹ️ Sin diferencias vs PitayaCore — no se propaga"
          fi

      - name: 🔄 Actualizar PitayaCore con los cambios del subdominio
        if: steps.diff.outputs.has_diff == 'true'
        run: |
          rsync -av --delete ./core/   _pitayacore/core/
          rsync -av --delete ./docs/   _pitayacore/docs/
          rsync -av --delete ./.agent/ _pitayacore/.agent/

          cd _pitayacore
          git config user.name "Sync Bot — ${{ github.repository }}"
          git config user.email "bot@batidospitaya.com"
          git add core/ docs/ .agent/

          if git diff --staged --quiet; then
            echo "ℹ️ PitayaCore ya tenía estos cambios exactos"
          else
            git commit -m "chore(core): update from ${{ github.repository }}@${{ github.sha }}"
            git push
            echo "✅ PitayaCore actualizado"
            echo "🔄 Se activará automáticamente sync-to-subdomains.yml en PitayaCore"
            echo "   que replicará a todos los subdominios y desplegará core/ en cada host"
          fi

      - name: 🧹 Limpiar directorio temporal
        if: always()
        run: rm -rf _pitayacore
```

## NOTAS IMPORTANTES PARA ANTIGRAVITY CODE

- **No modifiques la lógica de negocio** de los deploy.yml existentes (módulos, permisos, etc.)
- **El token en `receive-core-sync.yml`** usa `${{ secrets[github.event.client_payload.path_secret] }}` para resolver dinámicamente el path del host correcto según el subdominio
- **`propose-core-update.yml` puede crear un loop** si no se controla: el push al subdominio activa propose → que pushea a PitayaCore → que hace dispatch al subdominio → que ejecuta receive (no propose, porque receive no modifica core/ del repo local antes del push). El loop está controlado porque `receive-core-sync.yml` no tiene paths filter que reactive `propose`.
- **Si PitayaCore y el subdominio tienen el mismo contenido**, el diff no encuentra diferencias y ningún commit se genera, evitando commits vacíos
- Los directorios temporales `_pitayacore` deben limpiarse siempre con `if: always()` para evitar que fallen los checkout subsecuentes
